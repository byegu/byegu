## 제가 맡은 부분

인증·인가, 그림 활동 API, AI 분석 서비스의 백엔드 연동, 서버 PDF 리포트에 기여했습니다. AI 모델 개발과 인프라 전체는 제 개인 담당 범위가 아닙니다.

### 1. 사용자 인증 이후에도 자원 소유권 확인

로그인만 확인해서는 요청의 `childId`나 그림 활동 ID가 실제 사용자의 것인지 알 수 없습니다. 데이터 조회 전에 보호자와 아동, 아동과 그림 활동의 관계를 검사하는 공통 Validator를 Service 계층에 적용했습니다. 관련 단위 테스트와 MySQL 통합 테스트를 추가했습니다.

Refresh Token은 Redis에서 token family, 기기, 현재 hash와 TTL을 함께 관리했습니다. Lua Script로 검증·교체·TTL 갱신을 원자적으로 처리하고, 이미 사용한 토큰이 재사용되면 해당 family를 폐기하도록 구현했습니다. 이 내용은 제가 구현한 인증·자원 접근 검증 범위이며, 전체 시스템의 보안을 보장한다는 의미는 아닙니다.

### 2. 외부 AI의 응답을 업무 상태와 분리

정해진 분석 명세를 백엔드 AI Client로 구현했습니다. AI가 이미지를 읽을 수 있는 단일 사용 접근 토큰을 Redis에서 관리하고, 유효 시간을 60초로 제한했습니다.

응답의 분석 ID·필수 필드·상태를 검증하고, 요청 실패·타임아웃·서버 오류·응답 형식 오류를 구분했습니다. 같은 분석의 재시도에는 멱등 처리와 횟수 제한을 적용했습니다. 후속 리포트 생성이 실패해도 완료된 그림 활동은 `COMPLETED` 상태를 유지하고, 리포트 실패와 재시도는 별도로 관리했습니다.

필드·상태값이나 장애 처리에서 모호한 부분은 AI 팀에 확인했습니다. 전체 AI 계약을 처음부터 단독 설계하거나 모델을 개발한 것은 아닙니다.

### 3. 서버에서 같은 리포트 제공

서버 PDF를 정본으로 제공하기로 한 것은 팀의 공동 결정입니다. 저는 PDFBox와 openhtmltopdf를 비교하고, 레이아웃 수정에 필요한 좌표 계산을 줄이기 위해 PDF 전용 HTML/CSS 템플릿을 사용하는 방향으로 구현했습니다.

`ReportAssetResolver`가 저장소에서 PNG·JPEG 자산을 직접 읽도록 구성해, 서버가 인증된 이미지 URL을 다시 호출하지 않도록 했습니다. openhtmltopdf는 브라우저가 아니므로 flex·grid 대신 table·block 기반 레이아웃을 사용했습니다. 브라우저 화면과 PDF가 완전히 같다고 보장하지는 않습니다.

## 사용 기술

Java · Spring Boot · Spring Security · MySQL · Redis · MinIO · openhtmltopdf

## 결과와 회고

팀으로 SSAFY 공통 프로젝트 우수상을 수상했습니다. 개인 구현에서 중요하게 다룬 것은 정상 응답뿐 아니라 자원 접근 권한, 토큰 재사용, 외부 응답 오류와 리포트 실패 시의 상태입니다.

운영 성능 개선율이나 인프라 부하 테스트 결과를 제 개인 성과로 제시하지 않습니다. 이 페이지는 담당 범위와 구현 과정을 정리한 문서이며, 프로젝트 원본 코드를 배포하는 저장소는 아닙니다.
